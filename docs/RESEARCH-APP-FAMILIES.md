# App families: what breaks, why, and the general fix (2026-11-22)

Goal: one mechanism per *kind* of app, never a bridge for one product. Each row says how the family was found to fail, the
source that explains it, what PC-Control does now, and how it was verified on a real app.

| Family | Examples | What failed | Why (source) | General fix | Verified on |
|---|---|---|---|---|---|
| Apps that ask Windows where the mouse is | Blender, game engines, 3D tools | Claude's click landed where the **user's** mouse was | Blender's GHOST reads `GetCursorPos` for button events ([GHOST_SystemWin32.cc](https://projects.blender.org/blender/blender/src/branch/main/intern/ghost/intern/GHOST_SystemWin32.cc)) | The guard inside the app answers `GetCursorPos`/`GetMessagePos`/`GetCursorInfo` with Claude's point only while PC-Control delivers its click (import-table redirect, expiry tick) | Blender 5.2: clicks select the camera / menu entries where Claude points, real cursor elsewhere |
| Raw Input keyboards | Blender, games, Unity/Unreal editors | No key ever arrived; "type" and shortcuts impossible | Raw Input is delivered only to the foreground window; Blender ignores `WM_KEYDOWN`/`WM_CHAR` ([same file](https://projects.blender.org/blender/blender/src/branch/main/intern/ghost/intern/GHOST_SystemWin32.cc); [Blender devtalk on IME](https://devtalk.blender.org/t/enhance-support-for-ime-input-method-editor-in-windows/38159)); `PostMessage` cannot simulate keyboard input ([The Old New Thing](https://devblogs.microsoft.com/oldnewthing/20150925-00/?p=91511)) | PC-Control posts `WM_INPUT` with its own handle; the guard answers `GetRawInputData` for it, `GetKeyState`/`GetAsyncKeyState`/`GetKeyboardState` with Claude's modifiers, `ToUnicodeEx` with the exact character. Detected per process (`GetRegisteredRawInputDevices`), nothing app-specific | `tests/test_rawinput_live.py` (Blender: select, delete/undo, F2 rename with "Árbol ñ€😀", Text Editor) |
| Apps that warp or confine the cursor | 3D grab tools, games' mouse-look | Would move/confine the **user's** mouse | Blender's continuous grab uses `SetCursorPos` (same source) | A background app (user working elsewhere) cannot `SetCursorPos`/`ClipCursor`; it sees the point it asked for | `test_rawinput_live.py`: "g" in Blender, cursor and clip rectangle unchanged |
| Chromium family (CEF, Electron, PWAs) | Spotify, Discord, VS Code, Claude desktop, Brave | Page empty in the UI tree; black window when covered | Chromium exposes the page only with accessibility on and stops painting occluded windows (`--force-renderer-accessibility`, `CalculateNativeWinOcclusion`) | Detected by Chromium's own files next to the exe (Store aliases resolved through their reparse point); started with the flags | Spotify: search typed, results, play/pause, foreground untouched |
| Hidden web views publishing elements | Acrobat Reader's invisible upsell dialog | 45 phantom buttons over the PDF; OCR of the page dropped; `read`/`scroll` went to the phantom | A hidden browser view keeps its accessibility tree | Elements whose own child window is not what shows at their center are dropped (layered overlays like drag bars ignored); `read`/`scroll` use the same visible walk; content with no published text is read by OCR of the screen | Acrobat: look/read show the PDF text and real toolbar; no false positives on Spotify, Explorer, Terminal, Taskbar |
| Apps whose UI Automation is very slow | Premiere Pro (user report: freezes for minutes while a UIA client reads it, [Adobe community, Nov 2026](https://community.adobe.com/bug-reports-728/premiere-pro-26-5-2-windows-freezes-for-minutes-not-responding-media-pending-when-an-accessibility-ui-automation-tool-reads-the-window-1654452)) | Risk of freezing the user's app | Same report; older [Premiere ACR](https://adobe.com/accessibility/compliance/adobe-premiere-pro-win-2020-acr.html) says most structure is not exposed programmatically | One element taking > 1 s, or < 50 elements/s, marks the program: from then on it is read from pixels only | `tests/test_slow_tree.py` (simulated slow tree; normal app unaffected) |
| Games with anti-cheat | EasyAntiCheat, BattlEye, Vanguard... | A foreign DLL in the game can get the **user** banned | Anti-cheats flag injected modules | Nothing goes inside: the guard refuses at its single attach point; open_app and actions refuse with the reason | `tests/test_anticheat.py` (copy next to an EasyAntiCheat folder; control without it) |
| Qt apps | VLC, OBS, Telegram, KeePassXC | (works) | Qt uses UI Automation since 5.11 ([Qt docs](https://doc.qt.io/qt-6.2/accessible.html)) | none needed | VLC in `tools/realapps.py` |
| Office | Word, Excel, PowerPoint | (works) | COM object model | COM (existing) | existing suites |
| Java, Remote Desktop | Oracle Forms, mstsc | (works) | Java Access Bridge; pixels | existing | existing suites |
| The taskbar / tray | volume, clock, apps | Not a target at all | Shell windows were excluded | "taskbar" window; volume through Core Audio ([IAudioEndpointVolume](https://learn.microsoft.com/en-us/windows/win32/api/endpointvolume/nn-endpointvolume-iaudioendpointvolume), as [pycaw](https://github.com/AndreMiras/pycaw/) does); other buttons ask first | `tests/test_taskbar_target.py` |

## Not done, and why

- **Adobe Premiere Pro / After Effects**: need an Adobe account and a trial (sign-in and payment details are the user's). Acrobat
  Reader (installed) was tested. When installed, check: look (expect partial tree; the slow-tree guard protects), clicks by OCR id,
  keys (Premiere reads key messages; shortcuts through the in-app modifier state).
- **Shortcuts in apps that only take keys when focused** (Acrobat's zoom): delivered inside the app, no visible effect, and the
  answer says so instead of claiming success.
- **Other computer-use servers compared**: [Windows-MCP](https://github.com/CursorTouch/Windows-MCP)'s tool list clicks at screen
  coordinates and types into elements; no volume tool or Raw Input route appears in it.
