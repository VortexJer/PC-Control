# App matrix

Real apps installed on the test PC, through the MCP server with read-only tools (look, find, read, scroll). Route = what the
classifier chose: chromium (Chromium/CEF/Electron flags), raw-input (keys delivered inside the app), java / remote / java-off
(surfaces), slow-tree (read from pixels), and how look read it (uia, uia+ocr, ocr, image). Generated by tools/app_matrix.py.
Actions: click / type / key on safe targets (a new document, a search box, the address bar), each one VERIFIED by reading the
app back (the text is in the field, the display shows the result) - not by the tool's own word.

Run 2026-11-22 on the user's PC (37 apps), the display OFF for part of it (the user was away): apps that only draw while
visible (UWP Store apps: Calculator, Clock, Settings stay on their splash screen) could not load - see Known limits.

## Known limits found by this matrix

- UWP Store apps (Calculator, Clock, Settings) do not load their content while the display is off; with it on they are covered by `tests/test_store_focus.py`.
- VS Code's editor (Monaco) publishes no writable value: typing into it is refused rather than sent to whatever has the focus.
- Notepad++ 8.9 refuses the guard DLL (it only loads signed DLLs): PC-Control does not start it guarded and says so.
- Apps whose first window is a start screen (Office, LibreOffice) open the document in a NEW window: look at the app again (windows) before typing.
- Modern Notepad restores unsaved tabs between sessions: text typed in a test is kept by Notepad unless it is cleared.
- Some names differ by language and version; the matrix picks targets by name first, then by kind, as Claude would after a look.
